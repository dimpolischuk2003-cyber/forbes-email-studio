# Перевірка Forbes Email Studio 0.2.2

Дата: 15 жовтня 2026 року. Доповнення до встановленої версії 0.2.1 (скриншот production f4861f9).

## Підтверджено на скриншоті

Читання листів eSputnik, груп та службової історії працює. Наявний один службовий запис. Проба запису Blob повернула BLOB_WRITE_UNCONFIRMED. Сам цей код не підтверджує відсутність прав запису.

## Знайдений дефект

Код порівнював constructor.name зі строками назв класів SDK. Production-збірка Next.js мінімізує ці класи: зокрема BlobPreconditionFailedError має коротку назву. Через це штатне відхилення застарілого ETag у пробі вважалося помилкою, а повтор після справжнього конфлікту не виконувався. Аналогічно приховувалися окремі помилки доступу.

Попередні тести з реальним SDK залишали пакет зовнішньою залежністю, тому не відтворювали цю зміну назв. Новий тест, який мінімізує також SDK, відтворив BLOB_WRITE_UNCONFIRMED до виправлення та проходить після нього.

## Зміни

- Перевірки типів використовують instanceof із класами SDK; залежність від назв класів прибрана. Умовні записи ETag збережені.
- Проба показує конкретний етап збою. Сирі повідомлення провайдера, ключі й заголовки авторизації не видаються.
- Налаштування, журнал і повернення до редактора доступні без примусового збереження. Незбережений лист залишається у пам’яті вкладки; закриття вкладки й надалі викликає попередження.
- Версія підвищена до 0.2.2 для перевірки встановлення.

## Перевірки

- npm test: API, права доступу, CSRF, чернетки, відновлення, конкурентні операції, тест/запуск, статистика; справжній SDK із підставним HTTP у звичайному та мінімізованому бандлах.
- npm run build: production Next.js та TypeScript.
- npm run test:runtime: реальний production HTTP-сервер, авторизація, захист маршрутів, діагностика відсутніх налаштувань.
- node tests/verify-runtime.mjs --storage: та сама production-збірка Next.js, справжній SDK, OIDC зі штучним JWT і підставні HTTP-сервіси. Дві послідовні повні перевірки підключень мають пройти; перевіряються створення, читання, оновлення, відхилення застарілого ETag.

У тестах використовуються лише вигадані ключі. Прямого авторизованого доступу до живого Blob та eSputnik немає. Після встановлення потрібна перевірка на сайті: цей пакет виправляє відтворений дефект, але не є доказом успішного збереження у вашому live-середовищі. Взаємодія у справжньому браузері локально не перевірялася.

## Встановлення

Розпакувати ZIP, завантажити весь його вміст у корінь GitHub-репозиторію зі збереженням папок і заміною файлів, Commit changes у main. Нічого попередньо видаляти або змінювати у змінних Vercel не потрібно.

Після нового deployment Ready відкрити Налаштування → Перевірити підключення. Має відображатися 0.2.2. Якщо всі перевірки успішні, зберегти чернетку. Якщо ні — потрібен скриншот конкретного повідомлення з етапом.
