# Forbes Email Studio 0.2.3

## Підтверджено

У production 0.2.2 тимчасова проба Blob проходить, але збереження чернетки завершується BLOB_WRITE_CONFLICT. Це не доводить, що доступ до сховища заборонений. Попередня проба не перевіряла відповідність ETag уже наявної історії версії, яку приймає API запису.

## Зміни

Перед зміною історії читаються метадані об’єкта, актуальний вміст із useCache:false та Accept-Encoding:identity і повторні метадані. Якщо версія змінилася, читання повторюється. Для ifMatch використовується точний ETag API метаданих.

Прочитаний вміст має відповідати версії: порівнюються непрозорі значення ETag без слабкого префікса й зовнішніх лапок; за різних значень потрібен точний збіг контрольної суми вмісту з 32- або 64-символьним hex ETag. Стабільні метадані самі по собі не дозволяють запис поверх іншої версії. Застаріле тіло того самого розміру блокується до PUT.

Діагностика історії використовує той самий шлях читання, що й майбутній запис. Вона показує, чи відрізняються ETag завантаження та об’єкта, без видачі значень ключів, текстів або заголовків авторизації. Проба використовує більший тимчасовий файл і той самий механізм; файл історії під час діагностики не змінюється.

## Перевірено локально

- npm test — PASS. API, авторизація, CSRF, конкурентні операції, повтори, відновлення, тест/запуск, статистика.
- Реальний встановлений Blob SDK у звичайному й мінімізованому бандлах — PASS. Відтворено конфлікт старого коду, коли ETag завантаження не приймається API запису. Перевірено слабкі ETag, різні ETag представлення з відповідною контрольною сумою, зміну даних між читаннями, блокування застарілого вмісту того самого розміру, збереження конкурентної зміни, втрату підтвердження та очищення проби. HTTP-сервіси підставні.
- npm run build — PASS. Production Next.js і TypeScript.
- node tests/verify-runtime.mjs --storage — PASS. Справжня production-збірка Next.js і SDK; підставні HTTP-сервіси. Вже існуюча історія 8 КБ має інший ETag завантаження, ніж API. Створення, повтор того самого запиту без дублювання, відкриття, редагування й повторне відкриття чернетки проходять; початкова історія зберігається. Реальні листи не надсилалися.

Точний формат ETag живого файла користувача недоступний у цьому середовищі. Різниця ETag — перевірене пояснення можливого конфлікту, а не підтверджений діагноз вашого приватного об’єкта. Нова діагностика покаже відповідність версій на production після встановлення.

## Встановлення

1. Розпакувати архів, завантажити всі папки й файли разом у корінь GitHub-репозиторію, зберігши шляхи. Commit changes.
2. Після Vercel Ready відкрити Налаштування → Перевірити підключення. Версія має бути 0.2.3.
3. Перевірити блок Історія кампаній. За успішних перевірок зберегти тестову чернетку та відкрити її зі списку кампаній.

Змінні середовища, API-ключі й історію не потрібно скидати або видаляти. Виправлення посилань tinyglobby і @floating-ui/utils із попереднього пакета включено.
