Це діагностичне оновлення. Воно не означає, що причину помилки живого листа №4731919 вже визначено або виправлено. Попереднє повідомлення об'єднує кілька незалежних перевірок і не дозволяє встановити причину зі скриншота.

## Встановлення й отримання звіту

1. Розпакувати ZIP та завантажити всі файли й папки всередині у корінь GitHub-репозиторію зі збереженням шляхів. Зробити Commit changes.
2. Дочекатися Vercel Ready. Увійти на сайт у звичному браузері.
3. У цьому самому браузері відкрити https://forbes-email-studio.vercel.app/api/draft-diagnostics?id=4731919
4. Завантажиться файл draft-diagnostics-4731919.json. Прикріпити його до чату для аналізу.

Якщо браузер показує JSON замість завантаження, можна скопіювати його текст до чату. Якщо відповідь 404 — перевірити, чи саме production оновлено до версії 0.2.5.

## Що перевіряється

Звіт містить лише ID листа, версію збірки, коди причин, результати перевірок і типи відомих полів відповіді пошуку. HTML, текст листа, підписаний токен, ключі, email-адреси, значення налаштувань і вміст відповідей eSputnik у звіт не потрапляють.

- EDITOR_MARKER_MISSING / MULTIPLE: відсутня або повторюється позначка редактора.
- EDITOR_SIGNATURE_INVALID: позначка не підтверджується поточним секретом студії. Це саме по собі не визначає, чи секрет змінився, чи змінилася позначка.
- HTML_CHANGED: HTML, який повертає адаптер, не збігається з підписаним. Окремо перевіряються вихідний HTML і HTML після додавання CSS; це дає змогу відрізнити ці випадки без передавання вмісту.
- EDITOR_METADATA_INVALID / NAME_CHANGED / SUBJECT_CHANGED: не збігаються дані редактора, назва або тема.
- PENDING_CREATE_MISSING / NOT_RECOVERABLE / PENDING_ID_MISMATCH: немає відповідної незавершеної операції створення.
- REQUEST_OR_SETTINGS_CHANGED: поточна кампанія з поточними налаштуваннями не відповідає хешу початкового запиту.
- READY: перевірки відновлення пройдено на момент читання. Звіт сам нічого не відновлює.
- RECORD_EXISTS: службовий запис уже існує; ця дія не призначена для його скидання.

Поле search показує, чи розпізнано відповідь пошуку за унікальною позначкою, скільки рядків отримано і чи є в них потрібний ID. Значення невідомих полів не повертаються.

## Межі та перевірки

Новий GET /api/draft-diagnostics потребує входу, віддає no-store JSON як вкладення і використовує лише читання eSputnik та службового сховища. Правила відновлення, тестування і запуску залишилися чинними. Не потрібно видаляти дані або скидати змінні середовища. Залежності не змінені.

PASS: npm test; npm run build; production HTTP tests/verify-runtime.mjs і режим --ambiguous. Нові тести відтворюють відсутню позначку, неправильний підпис, змінений HTML, окремий CSS, змінену назву, змінені налаштування та нерозпізнану відповідь пошуку; перевіряють відсутність записів у сховище й витоку приватного вмісту. Власний кабінет eSputnik у тестах замінено ізольованим HTTP-сервісом. Живий лист №4731919 у цьому середовищі не перевірено, реальні листи не надсилалися.
