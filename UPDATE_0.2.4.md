# Forbes Email Studio 0.2.4

## Виправлена поведінка

Скриншоти production 0.2.3 показали збій відповіді eSputnik під час створення, після якого повторний запит блокується як незавершена операція. Меню «Кампанії» перед переходом викликало save(), тому помилка збереження скасовувала навігацію.

- Усі переходи меню змінюють лише відкритий розділ. Вони не запускають збереження та працюють під час очікування відповіді. Відкритий текст залишається у пам’яті редактора при переходах між розділами.
- Відкриття іншої кампанії або створення нового листа не викликає автоматичний POST. Якщо поточний текст не збережений, перед його заміною є підтвердження. Закриття чи перезавантаження вкладки й надалі викликає попередження; це не довготривале браузерне сховище.
- Невизначений CREATE повертає структуроване посилання на операцію та її етап. У кампаніях відображаються незавершені створення, зокрема зі старих версій без назви.
- «Перевірити збереження» шукає лист за унікальним тегом операції. Перевіряються підпис редактора, HTML, налаштування та відповідність незавершеній операції. Провайдер отримує лише GET; новий лист під час перевірки не створюється.
- Якщо відповідний лист знайдений рівно один, відновлюється його службовий статус. Якщо збігів немає, їх кілька або походження не підтверджене, повторне створення не запускається. Відновлення тестів чи запусків не дозволяється.
- Початок і непідтверджений результат створення записуються у журнал. Додано кнопку оновлення списку кампаній.

## Перевірки — PASS

- npm test: наявні API/SDK/безпекові перевірки, плюс втрата підтвердження створення, структуроване посилання на операцію, пошук і відновлення без дублювання, повтори, захист від підміненого HTML та кількох збігів, шаблони й CSRF.
- npm run build: production Next.js та TypeScript.
- node tests/verify-runtime.mjs; node tests/verify-runtime.mjs --storage; node tests/verify-runtime.mjs --ambiguous: реальна production-збірка з вигаданими ключами та ізольованими підставними HTTP-сервісами. Створення, відкриття, редагування, втрата підтвердження й перевірка того самого листа проходять.
- tests/verify-navigation.mjs: справжні React DOM події у jsdom. Стара навігація відтворила блокування. Нова відкриває кампанії без POST, зокрема під час незавершеного запиту; текст зберігається; перевірка не створює дублікат; скасування заміни залишає зміни в редакторі. Дочірні редактори ізольовані. Це не перевірка відображення у Chromium.

Для DOM-тесту потрібен jsdom 26.1.0 як окремий тестовий інструмент. Його можна встановити поза проєктом і передати шлях через JSDOM_MODULE_PATH. На роботу сайта або його залежності це не впливає. Режим --baseline у DOM-тесті навмисно повертає стару логіку й має завершуватися невдало.

## Встановлення

Розпакувати ZIP. Завантажити всі папки й файли всередині у корінь GitHub-репозиторію зі збереженням шляхів і зробити Commit changes. Після Vercel Ready відкрити сайт у новій вкладці, перевірити версію 0.2.4 у налаштуваннях і перейти у Кампанії. Біля незавершеного створення натиснути Перевірити збереження.

Змінні середовища, API-ключі та Blob не потрібно скидати. Попередні виправлення залежностей збережено.

## Межі

Точна причина збою відповіді живого eSputnik не встановлена: прямого доступу до ваших ключів та кабінету немає. Оновлення виправляє підтверджений дефект навігації й додає безпечний спосіб перевірити результат незавершеного створення. Воно не є доказом успішного відновлення саме вашої операції до перевірки на сайті. Реальні листи під час тестів не надсилалися.
