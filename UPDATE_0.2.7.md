# Forbes Email Studio 0.2.7 — збереження прехедера

## Причина

Після відновлення листа фактичний HTML редагується як імпортований шаблон. renderEmail() для такого шаблону не застосовував поле preheader. Після зміни HTML провайдером decodeMessage() відкривав фактичний HTML, але не читав з нього прехедер. Тому тема й текст кнопки зберігалися, а поле Preheader зникало після повторного відкриття.

## Виправлення

- Для імпортованих і вбудованих шаблонів прехедер записується в прихований блок HTML на початку тіла листа. Попередній розпізнаний блок замінюється; повторні збереження не накопичують копії.
- Підтримується клас esd-hidden-preheader, який використовує eSputnik, власний ID студії та старий блок студії з характерним стилем і трьома символами заповнення. Нерозпізнані приховані елементи, зокрема блоки з пікселями, зберігаються.
- При відкритті фактичного HTML прехедер читається з нього. Зміна форматування HTML або відсутність коментаря редактора не вимагає відновлювати старий текст із метаданих. HTML-сутності декодуються, заповнювачі прихованого прехедера не потрапляють у поле.
- Підтримується зміна та очищення прехедера. Символи <, >, &, лапки екрануються. Решта джерела HTML поза розпізнаними блоками прехедера зберігається без повторної серіалізації.
- Звичайне очищення редактора зберігає власний атрибут прехедера. Перегляд і формування HTML для тесту/розсилки використовують той самий механізм.

Прехедер зберігається всередині листа в eSputnik. Текст не додається до Blob. Права API, службові статуси й захист запуску не змінюються.

Офіційний опис прихованого прехедера й класу eSputnik: https://docs.esputnik.com/docs/how-add-hidden-preheader-email

## Встановлення та перевірка

1. Розпакувати ZIP. Завантажити всі внутрішні файли й папки в корінь GitHub-репозиторію зі збереженням шляхів → Commit changes.
2. Дочекатися production Vercel Ready. Відкрити сайт у новій вкладці; перевірити версію 0.2.7 у налаштуваннях.
3. Відкрити той самий відновлений лист. Вписати Preheader заново, наприклад «Перевірка прехедера 123», і зберегти.
4. Перейти у Кампанії, відкрити цей лист знову й перевірити тему, прехедер та текст кнопки.

Раніше введений прехедер, який не потрапив у фактичний HTML, потрібно ввести заново. Переналаштовувати ключі чи видаляти дані не потрібно.

## Перевірки

PASS: npm test; npm run build з чистим локальним кешем; npm ci --dry-run; production HTTP tests/verify-runtime.mjs, --storage, --transformed; DOM tests/verify-navigation.mjs з окремим jsdom 26.1.0.

Нові перевірки охоплюють запис, заміну й очищення прехедера; вбудовані та імпортовані шаблони; вкладену розмітку й сутності; українську та emoji; збереження решти HTML і нерозпізнаних прихованих блоків; некоректно закриту розмітку; відсутність дублікатів; читання актуальної правки з eSputnik замість старих метаданих; скидання результату тесту після зовнішньої зміни.

API-тест зберігає тему, прехедер і зміну кнопки в одному листі, повторно відкриває його іншим обробником після навмисної зміни форматування HTML і перевіряє HTML тестової відправки. Production HTTP режим --transformed перевіряє той самий цикл на справжній збірці Next.js з ізольованим провайдером.

Для коректного розбору HTML явно оголошено htmlparser2 12.0.0 — ця сама версія вже була встановленою залежністю sanitize-html. Записи встановлених пакетів, їхні версії та адреси архівів у lock-файлі не змінювалися.

Живі листи з цього середовища не надсилалися. Результат на листі користувача потрібно перевірити після встановлення. DOM-тест не є перевіркою відображення в Chromium.
