# Forbes Email Studio 0.2.6

## Підтверджені причини

Звіт production 0.2.5 для листа №4731919 підтвердив правильні позначку створення, підпис редактора, дані кампанії, назву, тему й відповідність незавершеній операції. Відрізняється лише HTML. Окремого CSS немає; точний характер зміни HTML зі звіту невідомий.

Пошук цього листа повернув об'єкт з числовим id та TotalCount=1. Попередній адаптер приймав масив або відомі обгортки масиву і відхиляв такий результат.

## Поведінка після оновлення

- Пошук розпізнає один об'єкт із коректним ID. Для відновлення кожен лист читається окремо й перевіряється. Якщо TotalCount вказує на неповну відповідь або знайдено кілька відповідних листів, автоматичне відновлення блокується.
- Якщо походження й незавершена операція підтверджені, а HTML відрізняється, «Перевірити збереження» відкриває фактичний лист для перегляду. На цьому етапі службовий статус ще не змінюється.
- У редакторі доступна кнопка «Прийняти версію eSputnik». Після перегляду та окремого підтвердження відновлюється статус чернетки того самого ID.
- Підтвердження підписане, діє 10 хвилин і прив'язане до користувача, ID, поточного вмісту, позначки операції та її хешу. Зміна листа після перегляду або зміна налаштувань відхиляє підтвердження.
- Фактичний HTML залишається імпортованим HTML після звичайного очищення редактором. Початкові блоки з підписаних метаданих не підміняють змінений лист. Аудиторія й час вибираються знову. Результату тесту немає; перед запуском потрібен новий тест.
- Відновлення виконує лише GET до eSputnik і запис службового статусу у Blob. Воно не створює копію, не змінює HTML провайдера і не відправляє лист. Наявні записи кампаній, зокрема непідтверджені тести чи запуски, не скидаються.

## Встановлення

1. Розпакувати ZIP. Завантажити всі файли й папки всередині у корінь GitHub-репозиторію зі збереженням шляхів. Натиснути Commit changes.
2. Дочекатися production Vercel Ready. Відкрити сайт у новій вкладці; у налаштуваннях перевірити версію 0.2.6.
3. Відкрити Кампанії → лист №4731919 з темою «тест» → Відкрити. Переглянути лист праворуч.
4. Натиснути «Прийняти версію eSputnik» та підтвердити прийняття показаної версії. Статус має стати «Чернетка».
5. Перевірити редагування і збереження цього самого листа. Далі вказати потрібну аудиторію й провести новий тест на свою пошту перед запуском.

Можна почати з «Перевірити збереження» біля незавершеної операції: при відмінності HTML вона відкриє той самий екран перегляду. Якщо в цьому редакторі є незбережений текст, його заміна потребує підтвердження.

Видаляти дані або змінювати ключі не потрібно. Граф залежностей не змінений.

## Перевірки

PASS: npm test; npm run build; production HTTP tests/verify-runtime.mjs, --ambiguous та --transformed; DOM tests/verify-navigation.mjs з окремим jsdom 26.1.0.

Нові API-тести відтворюють комбінацію з живого звіту: правильний підпис і операція, змінений HTML, одиночний ID. Перевірено збереження фактичного вмісту, відсутність дублювання/PUT/відправлення при відновленні, необхідність нового тесту, повторне підтвердження, підроблений/прострочений токен, зміну HTML після перегляду, невідповідність налаштувань, CSRF та неповний результат пошуку. Попередні тести походження, неоднозначних запусків і CAS залишилися чинними.

У production HTTP режимі --transformed ізольований провайдер змінює HTML, повертає один ID та втрачає підтвердження POST. Реальна збірка Next.js знаходить лист, показує фактичний вміст, блокує непідтверджене відновлення й приймає показану версію після підписаного підтвердження. DOM-тест перевіряє перегляд, блокування редагування до прийняття, скасування й підтвердження кнопки. Це не перевірка відображення у Chromium.

Живий лист №4731919 не змінювався з цього середовища. Результат його відновлення потрібно перевірити після встановлення. Реальні листи під час тестів не надсилалися.
